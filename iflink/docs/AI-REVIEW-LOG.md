# AI 产出评审记录

记录 AI 生成的代码/文案、人工检查了什么、结论是什么；对应补充材料附件 6.3。

**建议读者：**全员

对应团队补充材料附件 6.3“团队分工与 AI 产出评审记录”。 目的：记录哪些代码/文案由 AI 生成，谁检查了什么，是否进入试用版。 **不要伪造记录；没有发生的检查不要写“已通过”。**

## 1. 使用规则

**1.** 每个模块负责人每次让 DSH 产出**有实际功能影响**的代码或文案后，记录一行。

**2.** 不需要记录每一次小改；按“可交付的小任务”记录。

**3.** 人工检查至少包括：

    - 打开 demo 看效果；
    - 按验收清单点关键路径；
    - 检查隐私（摄像头、外部请求、儿童数据）；
    - 看 DSH 审查报告。

**4.** 结论只能是：

```
通过
修改后通过
不通过
仅参考，不进入版本
```

**5.** 正式试用版只允许 `通过` / `修改后通过` 的内容进入。

**6.** 不写儿童姓名、照片、联系方式、学校、真实试用数据。

**7.** 记录保存在 `docs/AI-REVIEW-LOG.md`，随仓库提交。

## 3. DSH 审查提示（建议每次复制）

```
请作为代码审查员，只审查这次改动，不要改代码：
1. 是否只改了允许目录；
2. 是否符合 docs/CONTRACTS.md；
3. 是否停止摄像头、释放模型；
4. 是否有外部网络请求或 CDN；
5. 是否包含儿童数据、密钥、原始画面；
6. 是否运行 typecheck/test/build。
用非技术语言报告，最后列出我需要手动检查的 3 件事。
```

把审查报告的结论摘要填到“人工检查”列，不要只写“DSH 说没问题”。

## 4. 隐私专项检查

每个涉及摄像头/存储的模块，交付前额外检查：

☐ 未点击不请求摄像头。

☐ 退出页面后摄像头停止。

☐ 没有把原始画面/关键点写入 localStorage、日志或仓库。

☐ 没有把儿童姓名、照片、联系方式放进代码/测试数据。

☐ 没有外部网络请求（MediaPipe 模型/wasm 本地）。

☐ 没有 CDN。

☐ 拒绝授权后仍有鼠标/触摸替代。

☐ 家长可清除本地记录。

## 6. 常见错误

| 错误 | 正确做法 |
|---|---|
| 写“AI 已完成”但没有人工检查 | 写清楚人打开了哪个页面、点了什么 |
| 写“准确率 95%”但没有测试 | 写“3 位成人 × 10 次，成功 X 次” |
| 把儿童测试视频放进仓库 | 不提交；只记录脱敏后的功能观察 |
| 直接照搬补充材料的同意书 | 按实际功能改写，补齐占位符，正式试用前送审 |
| 把 DSH 审查当最终责任 | DSH 是工具；模块负责人签字负责 |
